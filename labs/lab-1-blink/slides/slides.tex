\begin{frame}{What do we mean by `Arduino'?}
    \Large
    The word `Arduino' gets used for three different things:

    \vspace{.75em}
    \begin{itemize}
        \item[\textbf{1.}] \textbf{The platform} --- An open-source project and company producing hardware designs, software and documentation.
        \vspace{.5em}
        \item[\textbf{2.}] \textbf{The board} --- The physical piece of electronics in front of you. We will use the `Arduino Nano Every' board in this course.
        \vspace{.5em}
        \item[\textbf{3.}] \textbf{The language} --- The C++ based language, and its libraries, used to write your programs (called sketches).
    \end{itemize}
\end{frame}

\section{Arduino: The language}

\begin{frame}[standout]
    \LARGE Arduino\\
    \normalsize The language
\end{frame}

\begin{frame}{The Arduino language}
    \Large
    Arduino uses a C++ based programming language. \\

    Arduino programs are called `sketches'. \\

    The Arduino language has some similarities and some important differences from the MATLAB you have seen before.
\end{frame}

\begin{frame}{Arduino Vs. MATLAB}
    \Large
    \textbf{MATLAB} is a dynamically typed language.\\
    This means you can simply declare a variable and MATLAB will figure out what kind of memory is needed automatically:\\
    \vspace{-1.5em}
    \inputminted{matlab}{./src/matlab-variable.txt}

    \vspace{1em}
    \textbf{Arduino} is a statically typed language.\\
    This means when you declare a variable, you must let Arduino know what type of data is contained within the variable:\\
    \vspace{-1.5em}
    \inputminted{arduino}{./src/arduino-variable.txt}

\end{frame}

\begin{frame}{The data types you will need}
    \normalsize
    \inputminted{arduino}{./src/arduino-data-types.txt}
\end{frame}

\begin{frame}{Control flow: `if', `else if', `else'}
    \normalsize
    Code inside the curly brackets runs only when the condition is true. Compare values with $==$, $!=$, $<$, $<=$, $>$ or $>=$, and chain conditions with `and'  ($\&\&$) or `or' ($\|$).\\
    \vspace{-.5em}
    \inputminted{arduino}{./src/arduino-condition.txt}
\end{frame}


\begin{frame}{Pins: setting the mode}
    \normalsize
    Before a pin can be used, the Arduino has to be told which direction it works in. `pinMode' sets a pin to `INPUT' or `OUTPUT', and belongs in `setup' --- it only needs doing once.
    \vspace{.5em}
    \inputminted{arduino}{./src/arduino-io-mode.txt}
\end{frame}

\begin{frame}{Pins: reading and writing values}
    \normalsize
    `digitalWrite' sets an output pin `HIGH' (on) or `LOW' (off). `digitalRead' gives back the `HIGH' or `LOW' state of an input pin. These usually belong in `loop', where they happen over and over.
    \vspace{.5em}
    \inputminted{arduino}{./src/arduino-io-readwrite.txt}
\end{frame}

\begin{frame}{What goes in each function?}
    \normalsize
    \begin{columns}[t]
        \begin{column}{.47\textwidth}
            \textbf{setup() \textrightarrow{} `get ready'}\\
            Anything that only needs doing once, before the board starts doing its job:
            \vspace{.5em}
            \begin{itemize}
                \item choose whether a pin is an input or an output (`pinMode')
                \vspace{.25em}
                \item open a serial connection to the computer (`Serial.begin')
                \vspace{.25em}
                \item attach a servo, or start up a sensor library
                \vspace{.25em}
                \item give global variables their starting values
            \end{itemize}
        \end{column}
        \begin{column}{.47\textwidth}
            \textbf{loop() \textrightarrow{} `do the work'}\\
            Anything that has to happen over and over for as long as the board is powered:
            \vspace{.5em}
            \begin{itemize}
                \item read the inputs (`digitalRead', `analogRead')
                \vspace{.25em}
                \item decide what to do with `if' / `else if' / `else'
                \vspace{.25em}
                \item drive the outputs (`digitalWrite', `analogWrite')
                \vspace{.25em}
                \item wait before the next pass (`delay')
            \end{itemize}
        \end{column}
    \end{columns}
\end{frame}

\begin{frame}{Step 5: Write, compile and upload your sketch}
    \Large
    \textbf{Compile:} `Sketch' \textrightarrow `Verify\textbackslash Compile'.\\
    This checks your code for errors without sending anything to the board.

    \vspace{1em}
    \textbf{Upload:} `Sketch' \textrightarrow `Upload'.\\
    This compiles the sketch and then sends it to the board.

    \vspace{1em}
    \normalsize
    A red warning about being unable to locate `flash' is normal on the Nano Every and can be ignored.
\end{frame}

\begin{frame}{Step 6: Open the Serial Monitor}
    \Large
    The Serial Monitor shows you the messages your Arduino sends back: `Tools' \textrightarrow `Serial Monitor'.

    \vspace{1em}
    It opens in the bottom section of the IDE, next to the `Output' tab.

    \vspace{1em}
    Set the baud rate drop-down to \textbf{9600}. This must match the value you passed to `Serial.begin' in your sketch, or you will see random characters instead of words!
\end{frame}
